## Goal

The scalable unit of lifting is one connected Portable-C operation, not one
enumerated execution path and not a hand-shaped `init`/`step`/`finish` API. The
compiler is trusted to lower ordinary C. The remaining proof obligation is that
the ordinary C operation and the exact generated Behavioral-C operation have
the same observable behavior in every admitted shared machine world.

The production authority chain is:

```text
ordinary C + V5 interface/binding + authored sync relation
  -> component-proof-plan-v1
exact Behavioral-C closure
  -> component-exact-c-slice-v1
plan + exact slice + shared-world CBMC shards
  -> contextual-refinement-v2
  -> semantic-provider-qualification-v2
  -> implementation-selection-v2
qualified objects + one strong module dispatch registry + linker map
  -> portable-dispatch-link-receipt-v1
  -> native-realization-v2
```

No source-only receipt, test, finite path set, status projection, or weak linker
symbol can skip a stage in that chain.

## Explicit scalar failure outcomes

A machine result binding can designate error values returned by ordinary C:

```json
{
  "id": "removed",
  "projection": {"kind": "register", "register": "eax", "width": 32, "at": "exit"},
  "fault_outcomes": [{"logical_value": 4294967295, "kind": "memory_fault"}]
}
```

The implemented scope is one unsigned 32-bit logical result with an unencoded
32-bit exit-register projection. Cases must be nonempty, sorted and unique by
value; supported kinds are `memory_fault` and `external_fault`. Other values
retain the ordinary result projection and return/continuation behavior. Fault
cases are rejected on parameters, encoded results and unsupported result types.
They participate in binding and semantic identity, so changing a case changes
the proof inputs even if the C signature stays the same.

The generated machine adapter checks the designated value after the operation
and existing fault channels, before publishing the normal result, exporting
normal state or consuming the return epilogue. Preceding memory and service
effects remain observable. The logical provider thunk retains the scalar result
and sets the enclosing caller's corresponding fault channel. Views retain their
existing lifetime-safe access context; no pointer to operation-local fault state
is stored in a returned view.

This mapping declares transport, not a theorem that an error value correctly
represents a fault. The paired proof still compares actual outcome kinds,
effects and public memory. No allocation failure, view-access error or familiar
sentinel acquires this meaning implicitly. In particular, the real cleanup's
empty-input path returns normally after a null allocation, while its nonempty
path attempts a failing write. Conditional examples of these paths do not prove
the production memory policy, caller premises or a composed summary.

## Proof shape

`SPX_PROOF_BEGIN(operation)` and `SPX_PROOF_SYNC(sync, ...)` are zero-cost
production annotations. During proof compilation they become forced control
barriers. An operation has one entry obligation plus one obligation per authored
synchronization point. Acyclic operations without syncs retain a single entry
obligation. Syncs may cut acyclic regions as well as cyclic SCCs, but removing
all cutpoint units must leave an acyclic exact control graph. Every region
retains all successors up to its next barriers; no complete paths are enumerated.
Source barriers must match the authored inventory and prove the connecting
relation. A cut outside a cycle does not discharge that cycle.

A declared exit block can also have successors inside the operation. Canonical
V5 closure uses the declared replacement ownership to retain those internal
edges, including a loop header's early-exit alternative and a loop latch's
back edge. Selected exact epilogues remain proof context rather than becoming
replacement ownership. Owned units must be reachable, continuations must remain
outside ownership, and an undeclared outgoing edge or an exit label with no
outgoing boundary fails closure. The contextual control graph retains internal
edges from exit blocks, so their cycles still require proof cuts. The older
path-segment builder rejects such mixed exits instead of dropping successors.

The native adapter can lower multiple owned direct exit blocks to one outgoing
boundary when every block has exactly one external destination and all agree on
the exact outcome kind and target RVA. Internal branch alternatives do not
become adapter exits. Different targets, mixed outcome kinds and ambiguous
control-result projections still reject. This structural choice does not prove
the authored operation reaches that boundary: the ordinary contextual engine
still checks control, current state, memory, interactions and cut alignment,
including any explicitly selected exact continuation.

An outgoing source marker terminates its proof region on every path. It must
match the exact side's corresponding cut; an exact return, fault or different
control destination fails alignment. An unexpected marker also fails and stops.
The initial visit used to resume an incoming relation remains distinct and
continues execution. This is the matched-barrier rule, not a rule permitting
source cuts to be crossed while searching for a later matching fault. Such
unmatched steps would require a separate progress and composition rule.
The checker policy binds `source-cuts=matched-terminal-v1`; both independent
readers require outgoing alignment and applicable unexpected-marker evidence.
Earlier receipts without this policy do not satisfy current authority.

An operation may explicitly declare `source_unwind_limit` (an integer in
1..65536) in its bisimulation intent. This permits finite internal source loops
without adding synchronization points or production functions. The canonical
plan records the limit under `source` and retains the actual lexical and
annotated loop counts; `source_lexical_loops_cut` remains false when some loops
are internal. Exact control cycles must still be cut as before. Without the
declaration, an unannotated lexical source loop is rejected during planning.

The limit is a checker resource choice, not an assumed trip count or an input
precondition. It replaces the default global unwind limit in property, safety
and nonvacuity queries; existing checked helper-specific bounds remain explicit.
These queries also require `--no-self-loops-to-assumptions`, so an empty
divergent loop cannot silently become an assumption. Unsliced unwinding checks
must establish sufficient expansion for every admitted path before same-entry
assertions can reuse that result. Focused entries retain their own checks.
An insufficient bound, divergent loop or timeout cannot qualify the operation.
Python and JQ readers bind the commands to the planned limit and progress option.
Changing the limit changes the intent, plan and query identities. This rule
does not establish an inductive invariant or the caller premises of a sync.

For identity scalar captures, the harness can also admit the existing cut
invariant before exact execution. Eligibility comes from the source compiler's
lexical storage inventory: referenced values must be unambiguous, nonvolatile,
unsigned 32-bit C words, transported through identity codecs from entry registers,
private stack slots or image scalars. The complete supported Boolean expression
is projected; unsupported operands, codecs, source lvalue bindings and wider or
signed types retain source-side admission. Checked input readers still establish
the observations used by memory projections. The same admission is present in
the relation witness, and all source restoration, capture/roundtrip, predecessor
invariant, coverage and progress checks remain. This is a type-preserving
reordering of the existing relation, not an additional operator premise or a
new summary capability. Changed harness bytes require their normal new evidence.

The sparse proof runtime selects an allocation record into a local snapshot
before inspecting its lifetime, history visibility or initial bytes. Selection
uses fixed array elements and rejects an index outside retained storage. It
preserves lookup precedence, retired generations, whole-span checks, one-past
handling and the distinction between current incoming bytes and birth values.
Public/private write logs and incoming-byte logs likewise lower their bounded
appends to constant-index branches after the existing counter update and
capacity assertion/assumption. A full log still fails; no record is silently
dropped. These are checked implementation changes to the existing proof world,
not abstract heap summaries or new caller premises. Differential CBMC checks
cover arbitrary metadata and log contents, including neighboring records and
failure outcomes. Complete consuming proofs and their normal evidence bindings
remain required.

Each obligation:

1. constructs an arbitrary shared input world;
2. assumes the declared entry relation, or the relation at a checked cutpoint;
3. executes the exact Behavioral-C segment and the corresponding ordinary-C
   segment;
4. proves ordered typed service and atomic interactions equal;
5. proves the same return/control result and every declared final state or
   memory observable, or re-establishes the relation at the next barrier,
   including equal public memory and paired connected calls before terminating
   that proof segment.

At a synchronization boundary, a fresh arbitrary public address is compared
through both effective-byte memories. This checks the shared memory assumed by
the successor obligation without requiring equal write order, width, or count.
Private implementation storage remains governed by the declared capture and
state relation. Memory equality and connected-call pairing are independently
required assertion descriptions; the aggregate reader derives these obligations
from selected units and outgoing cutpoint edges and rejects an omitted check.
Old receipts without the strengthened cutpoint policies are not strong authority.

Allocation history has an additional cut-entry obligation:
`spx-bisimulation-allocation-cut-admission:<sync>`. Without an explicit history
declaration, resumed regions initialize empty allocation histories. Each
predecessor must therefore prove both histories empty before taking that cut.
Equal nonempty histories do not establish the resumed premise. Released instances also count: erasing their
generations could revive stale references. A null allocation creates no instance
and does not by itself prevent a cut. The generated assertion and independent
Python/JQ inventories enforce this restriction even when no view is captured.
This does not require allocations to succeed or classify a successful allocation
as an original program fault. Decoding a local pointer alone cannot discharge it.

The sparse world now has an incoming-allocation constructor for developing that
transport rule. It restores ordered instance metadata, including retired rows,
ownership, native generation and checked allocation-class provenance. Incoming live rows
read the region's arbitrary current input bytes; their recorded birth-time
initialization is not replayed. Later allocations still use their own fresh
initialization and generation. Write/shadow history offsets are rebased because
the prior effects belong to the incoming memory relation. Construction rejects
malformed generations, overlapping live storage, duplicate native generations,
capacity overflow and insertion after region effects.

A hand-defined sync can now declare the bounded history that its resumed world
accepts, using the existing sync intent:

```json
"allocation_history": {
  "maximum_instances": 1,
  "classes": ["cleanup.scratch"]
}
```

The bound includes retired generations, not only live instances. Class names
must be sorted and unique, and resolve through checked allocation requirements
or native class correspondence. The consumer need not contain an allocating
service: recipes depend on the full checked class contract, not local call sites
or service names. Any supplied allocating calls still require their full ABI and
effect checks. A stable name or declared effect cannot supply the selected
allocation contract. The outgoing check validates both histories
against those classes and the successor's stack frame, using the same metadata
predicate as construction. The resumed harness restores paired arbitrary histories
before decoding views or registering origins. Existing public-memory equality
establishes current-byte correspondence; birth initialization is never substituted
for that relation. Storage reserves the declared input capacity plus the region's
bounded new calls.

The transport policy is
`bounded-allocation-history-checked-class-current-memory-v2`; Python and JQ
readers reject the previous call-identity-based history policy. It does not
establish actual caller admission, select the reachable caller heap footprint,
or prove that unrelated allocations are framed.

Operation and segment evidence must bind
`allocation_history_policy: bounded-allocation-history-checked-class-current-memory-v2` and
the operation's exact `maximum_input_allocations`. Both receipt readers reject
missing or mismatched metadata, and require
`spx-bisimulation-allocation-history-input:<sync>` for each declared resumed region.
Outgoing allocation admission and memory checks remain independently required.

An operation can declare `entry_allocation_history` with the same fields as a
sync's `allocation_history`. This is an explicit **conditional entry premise**.
Both property and reachability harnesses construct its paired current-memory
history before decoding parameters. They require the shared restoration check
`spx-bisimulation-allocation-entry-input:<operation>` and the constructor-domain
check `spx-bisimulation-allocation-entry-admission:<operation>`. These checks
validate construction under the premise; they do not prove an actual caller
satisfies it. The reserved input capacity is the maximum across operation entry
and all sync histories, plus the shard's call capacity for new allocations.

A locally satisfied proof with this field has `activation_authorized: false`.
The checker reports `bisimulation_entry_allocation_admission_required`, Python
and JQ reject activation, and provider qualification remains incomplete even
when a common continuation context is available. Checked caller-footprint,
current-content, lifetime and frame discharge must be implemented before such
a conditional supplier can enter an activated component network. A declared
history is not a complete process-heap model or a native lifetime receipt.

A cut may additionally transport the invocation's existing private-stack scope:

```json
"private_stack_scope": { "register": "ebp", "offset": 4 }
```

This pure PE32 register-affine projection is evaluated without wrapping. The
entry region establishes its scope at entry ESP. Each resumed region constructs
the semantic private interval from its projected scope, while its affine stack
cache and region access footprints remain anchored to that region's entry ESP.
Allocation history and view admission use the projected scope consistently.
This prevents a prologue's ESP adjustment from reclassifying adjacent live heap
bytes as private at a cut. It does not prove that the interval is private to all
real callers, establish stack-object lifetime, or authorize a visibility change.

Once any sync in an operation declares this field, every outgoing cut must prove
`spx-bisimulation-private-stack-scope:<sync>`: its successor's projection equals
the current invocation scope in both worlds. A sync without an explicit field
uses its reached ESP as that projection. Explicitly scoped successor constructors
also check `spx-bisimulation-private-stack-scope-input:<sync>`. Both independent
readers require the applicable checks and bind operation and segment metadata
`private_stack_scope_policy: checked-invocation-private-stack-scope-v1`.
The field participates in intent and proof-plan identity. Older unscoped intents
retain their existing entry-ESP interpretation; they do not demonstrate stable
invocation-scope transport. Recursive or dynamically changing frames need further
checked per-instance rules before this profile can represent them.

This rule transports allocation metadata and current memory. It does not import
an arbitrary logical-origin registry, reconstruct an arbitrary source-local view,

## Scaling contract

Native parameter-view admission enrolls references independently through the
exact and source runtimes before executing a region. The mandatory shared-view
input check requires exact resolution to succeed and both canonical reference
tuples to agree, in addition to the exposed-view count. This restores issued
origin evidence needed by exact services at resumed cuts. It does not copy
current memory, grant a permission absent from the authority, or revive a dead
allocation. Byte/frame/lifetime and service result obligations remain separate.
Existing checked 32-bit register-literal derived facts are also admitted before
exact execution; all predecessor derived assertions remain. Other source-dependent
relations still require source reconstruction and do not become early machine
premises merely because they appear in the same cut.

The proof plan is linear in graph barriers, control edges, and reachable checked
internal-direct call edges rather than in complete paths. It records zero
materialized paths. Each obligation has:

- an exact-C slice specialized to the units before the next barrier;
- a proof header specialized to its one start and immediate target barriers;
- obligation-local memory, call, and atomic bounds;
- one GOTO model shared by assertion, paired language-safety, and nonvacuity
  queries;
- bounded formula-sliced authored-assertion groups plus complete property-class,
  intrinsic-baseline, and reachable-loop inventories;
- paired-entry language-safety partitions over those inventories, with bounded
  groups of at most 1,024 sorted property IDs under V13; legacy V11/V12 group
  large non-unwinding classes by owning function;
- property-specific, assertion-then-stop prefix entries for typed service
  equalities;
- an optional generated affine stack-word cache with partial-overlap invalidation
  and chronological log fallback;
- stable entry points and command/model digests bound into the receipt.

Each safety policy derives every group from the complete static inventory.
Small classes and unwinding remain whole. V13 packs non-unwinding IDs across
helper functions to share symbolic processing, keeping the paired entry and
instrumentation unchanged; it does not combine different safety classes or
input worlds. V11/V12 retain their original function-owned groups. The producer,
Python reader and independent JQ reader require the selected policy's canonical
group order and exact property coverage; omission, duplication, reassignment
across canonical groups and unknown classes fail closed. All safety groups must pass before authored assertion
queries run. Grouping changes query identity, not the paired proof entry or its
language-safety obligations. Each supported strategy remains bound to its
declared command policy.

The V12 and V13 authored strategies keep the first scheduled assertion separate, then
groups up to four consecutive properties only when their entry, source owner
and instrumentation agree. Timeout or out-of-memory groups split into smaller
queries on the same compiled bytes; parent attempts remain diagnostics and only
the complete child coverage discharges the group. Both readers check selected
IDs, order, owners, entries and counts. A satisfied shard cannot contain an
incomplete or violated query. The V11 single-property strategy remains valid
under its original receipt shape. Changing strategy does not authorize reuse
of different query commands: exact model, tool and argument bindings still
govern every cached result.

When a group has no reusable exact result but its complete binary subdivision
does, the scheduler selects those cached children directly. This avoids retrying
an exhausted parent merely to rediscover its already checked children. Every
child retains the original model, entry, instrumentation and exact arguments,
and its output is reparsed normally. Cached counterexamples still reject;
missing children leave the original group scheduled, and corrupt or unbound
outputs fail closed. This applies to authored and non-unwinding safety groups;
unwinding remains whole. The existing independent coverage readers and receipt
formats are unchanged. Cache availability is a scheduling hint, never a proof
result or permission to omit properties.

V13 is the SAT default. The SMT default retains V11, including its existing
safety grouping. A timeout or memory-exhausted safety group may subdivide only
within its own ordered ID set, and complete success still requires every ID.
Evidence for one grouping cannot discharge a different canonical grouping;
each strategy is checked against the actual selected IDs. A stable model digest
alone does not validate a different query plan.

A finite-control operation additionally records its route-inventory digest in
the obligation model and carries one feasibility witness per selector value in
the same compiled goto model. This is linear in the table size and does not
materialize one execution path or one build derivation per route.

Obligations execute sequentially, while up to four assertion queries within the
current obligation execute in parallel inside the content-addressed provider
build. This single-axis schedule caps the provider at four CBMC processes;
nested obligation/query pools cannot multiply the memory budget.
Operation-wide interface parsing, capture templates, generated overlays, and
exact-slice metadata are shared. The aggregate receipt is canonical and
sorted, so a failure identifies one stable entry/sync obligation and,
for properties, one stable CBMC property ID.
The Nix cache boundary remains the component provider; splitting every short
solver call into another public artifact is not justified unless measurements
show that cross-build shard reuse outweighs scheduler and registry cost.

## Native activation

A satisfied proof qualifies object bytes but does not by itself prove that the
candidate calls them. Native construction reopens the selected qualification,
checks the contextual proof, proof plan, exact slice, overlay inventory, and
object manifest identities, and then generates the sole strong module-wide
dispatch registry. Before linking it requires exactly one strong implementation
symbol for each selected overlay and forbids any pre-existing strong or weak
registry definition. After linking it binds every overlay and all registry
symbols to linker-map RVAs and binds the receipt to the exact payload and
selection.

The registry is compiled against the one shared state-machine runtime ABI,
not against any component's slice-local `behavioral-c.h`. Component prototypes
are intentionally specialized to their exact slices; requiring those headers
to be byte-identical would create a false module-wide ABI constraint. The
small dispatch declaration shared by slices and registry is emitted from one
renderer, while the build still requires one identical state-machine runtime
header across all selected objects.

`native-realization-v2` validates that receipt against its selected Portable-C
definitions and native-object inventory. SDK candidate, test-suite, aggregate,
and deployment gates require complete activation with
`source_only_authority == false`, including the vacuous complete receipt for a
configuration with no selected Portable-C definitions. The aggregate
constructor has no receipt-free mode: `nativeRealization` is mandatory and is
strictly parsed before the candidate process starts.

The qualified runtime is deliberately selection-independent. It validates the
linked override table structurally—sorted unique transfer RVAs, real Behavioral-C
units, non-null functions, no fallback, and self-consistent lookup—but does not
embed a second pre-selection copy of provider choices. Exact provider identity,
object membership, registry ownership, and symbol/link RVAs are already checked
by the content-addressed dispatch/link receipt. Keeping that authority in one
place avoids both contradictory runtime metadata and a dependency cycle from
runtime qualification back through later provider selection.

## Completion checklist

- All pilot proof plans contain zero materialized paths and exact forced-label
  barriers.
- Every contextual shard is satisfied, or the pilot remains explicitly
  incomplete with its exact stable shard blocker.
- Qualified provider dependencies name the contextual proof, proof plan, and
  exact-C slice identities.
- A selected portable candidate contains exactly one strong dispatch registry,
  exact implementation symbols, and a payload/link-map-bound receipt.
- Native realization and every execution/deployment gate reject missing, weak,
  duplicate, source-only, stale, or partial authority.
- Focused unit tests, format/index refresh, target proof gates, native PE32
  integration, and repository checks pass before this migration is complete.

An existing derived relation whose projection is a machine register and whose
expression is `exact_stack_address` also constrains the resumed original input
before original execution. The harness emits that pure relation from
`initial_state`, as well as retaining the source-header input assumption and
every outgoing derived assertion. For example, a predecessor can establish
EBP=ESP+28 and its successor can check a write through EBP-8 against the private
ESP+20 footprint. Admitting the relation only during later source resumption
left the earlier original frame query checking unrelated EBP values.

This is ordering of the existing cut contract, not an additional input premise
or a new public format. The relation-only query retains nonvacuity checking,
false relations must fail their predecessor, and undeclared relations are not
inferred. Source-dependent derived expressions still wait for reconstruction.
The changed harness and proof models remain bound through the existing evidence
chain.

A current machine-to-machine scalar fact can use `exact_projection` on the
right side of an existing derived relation. For example:

```json
{
  "id": "length_target",
  "projection": { "kind": "register", "register": "ebx", "width": 32, "at": "entry" },
  "expression": {
    "op": "exact_projection",
    "projection": { "kind": "static_slot", "rva": 57688, "width": 32, "at": "entry" }
  }
}
```

Both operands must be canonical entry-register, image-scalar or stack-word
projections of equal width (8, 16 or 32 bits). Image-relative scalar ranges must fit the proof
image. This profile excludes source expressions, views, EIP and historical
snapshots. At a predecessor, `entry` denotes the reached cut relation and the
image read uses **current exact memory**. The register must still match after
any intervening write or aliasing service effect. A successful earlier load does
not establish import-slot stability.

The successor admits the same equality from `initial_state` and checked input
memory before either implementation executes. The header retains the resumed
assumption and outgoing assertion. Faulting projection reads are independently
checked, not silently erased by the equality assumption. Operation and segment
models without stack facts bind `machine_fact_policy: checked-current-machine-cut-facts-v1`.
Python and JQ readers require each consumed predecessor fact assertion and the
applicable checked input/output-read assertions. This transports a conditional
cut premise; it supplies neither a loader contract nor actual caller admission.

Stack-word facts use the existing `stack` projection with a signed offset in
`[-4096, 4096]`, measured from ESP at the particular cut. For example, the real
producer's service-argument boundary states that stack word 0 equals stack word
36 (the pushed handle equals the retained caller handle), and stack word 4
equals EBX (which the preceding region sets to zero). These are facts about
current contents, not reconstructed pointers or copies of historical slots.
The output side reads the predecessor's current memory; the resumed side
constrains its initial current-memory map before either implementation executes.
Every predecessor must establish the equality again after its intervening writes.

Models containing these facts use
`machine_fact_policy: checked-current-stack-machine-cut-facts-v2`. Their input
and output readers check signed 64-bit address arithmetic before conversion
to a machine address: the complete word must fit the 32-bit address space.
The existing checked memory readers still establish defined access. Both receipt
readers require the applicable `spx-bisimulation-exact-{input,output}-stack-range`
and read assertions, plus the predecessor's derived-fact assertion. A legacy
policy or missing guard cannot qualify a stack-fact model. This does not make
stack-relative memory private, establish ownership or lifetime, permit a new
production API, or independently authorize component composition.

Source locals at a resumed cut must overapproximate the actual state at that cut.
Re-running their entry initializers is insufficient. The compiler-derived scope
and write inventory now selects visible local objects for havoc before declared
captures are restored. Only closed constant values and unchanged direct aliases
of local storage can be retained from the prefix. An initializer reading inputs
or memory is not treated as a cut-state fact. Shadowed mutable objects that
cannot be named unambiguously are rejected. Inventory failures are fail-closed;
the inventory is diagnostic and the resulting proof header is bound as a proof
input. Current Python and Nix readers require the expanded local-and-parameter
storage policy below and reject older receipts lacking it. Source context transport is
also preserved independently on both sides of a scalar empty-frame summary.

For resumed operations, BEGIN must occur in the outer function block. The
re-executed prefix may initialize automatic locals but cannot invoke effects,
write nonlocal storage, or bypass BEGIN. The local inventory is a mandatory
proof input for operations with source cuts, rather than an optional policy
claim. Prefix and scope restrictions fail with diagnostics and remain explicit
limits of this implementation.

Each sync may capture a different set of local source values. A value captured
at an earlier sync is not implicitly available at a later one. Exported state
and non-scalar interface parameters still require reconstruction at each cut;
the compiler storage inventory overapproximates other live storage. The three-region
solver fixture covers a local that dies before the final cut and a distinct
final-result local. It rejects using an omitted earlier local or violating the
incoming final-value relation. Unexpected-marker alignment assertions remain
in one shared helper per marker, called with false at real unexpected visits.
A harmless true call from the harness keeps the assertion
in the compiler inventory even when resuming bypasses that marker's lexical
block; it does not assume alignment for real visits.

Automatic parameter objects also belong to the cut's source storage. Any
parameter assigned in the function or exposed by taking its address is havoced
on resume before captures restore the relation. This includes a reassigned
context pointer: restoring the original pointer would lose the actual source
state. Captured unchanged parameter values retain their checked interface realization;
unchanged direct aliases to parameter storage retain the address, not its value.
A context-pointer regression previously falsely passed and now produces a
counterexample. Both readers now require `source_cut_storage_overapproximated`
and the bound `source_cut_storage_inventory` input for operations with cuts.
These replace the earlier local-only policy and inventory role; historical
receipts cannot be upgraded by merely renaming the policy field.

Parameter value relations must also refer to the correct C argument object.
The compiler's ordered function parameters are matched to the interface. A
logical parameter capture may
name the actual renamed argument, but cannot bind another local, a different
argument, a member path, or a shadowing declaration. The previous record-view
fallback cannot bypass this production check: cut admission requires explicit
parameter relations for non-scalar arguments, with unsupported structured reconstruction rejected.
The compiler binding inventory is a separate required proof input,
`source_parameter_binding_inventory`, and both readers require
`source_cut_parameter_bindings_checked`. This closes a reproduced false
acceptance where a constant local stood in for a still-live original argument.

A cut may omit an 8-, 16-, or 32-bit integer argument decoded from a register or
stack slot. The compiler must identify its actual argument object and include
it in that cut's storage havoc, even if the function never assigns it. The
resumed proof makes the omitted value arbitrary before restoring the declared
captures; it does not reconstruct or assume its operation-entry value. An
unchanged alias to the argument keeps its address and observes the havoced
value. Shadowing that prevents havoc from naming the argument is rejected.
Pointer, view, resource and aggregate arguments still need explicit relations.
This is overapproximation, not a liveness assertion: if the remaining source
depends on the forgotten value, the ordinary equivalence or definedness proof
must fail unless the declared relation suffices. Setup-only parameters can
therefore disappear from a loop's capture vector without changing its C API.
The existing bound storage and parameter inventories record this choice under
`omitted_scalar_parameters`; the generated proof header remains a hashed proof
input. No separate summary or activation authority is introduced.


Capture codecs must preserve the actual source value, not merely match an
encoded machine word. Parameter captures now require the canonical argument
encoding used by reconstruction: the scalar value, byte-view address, or resource
identity. Arbitrary parameter transformations have no supported decoder and are
rejected. Source-state machine codecs retain their authored decoders, but each
incoming transition must prove both the forward encoding and that decoding the
machine projection reproduces the captured C value. The latter assertion is
`spx-bisimulation-capture-roundtrip:SYNC:CAPTURE`. Both readers independently
require it for every machine-coded source-state capture at a reachable next cut;
Nix also checks canonical parameter encodings directly from the proof plan.
Removing the required round-trip check or ignoring a parameter's value cannot
be hidden by rehashing an inventory. This supersedes receipts predating the new
round-trip assertions, even if their storage and argument-binding flags exist.
