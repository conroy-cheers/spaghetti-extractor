## Decision

flowed through the public mapping, relation-contract, preparation, distributed

## Performance

- Corpus generation: approximately 0.51 seconds.
- Static proof preparation: 0.21 seconds after the implementation was present
  in the development environment.
- Distributed proof build and audit: 675.27 seconds, using acacia and banksia.
- Slowest isolated acceptance leaf observed: 739.37 seconds, one core and
  approximately 1.7 GiB RAM.
- Fresh output directory with the independently regenerated corpus and all Nix
  derivations cached: 0.90 seconds, including 0.23 seconds of preparation and
  0.67 seconds of Nix realization/audit.
- Identical warm rerun: 0.009 seconds, with both preparation and proof/audit
  reported as content-cache hits.

The slow leaf is now independently cacheable. Acceptance chunks import only
the segment-refinement modules for edge IDs they use; the shared acceptance
context no longer imports the aggregate of every segment proof. A change to an
unrelated segment therefore does not invalidate all acceptance leaves.

## Repairs Required By The Canary

The canary exposed four generic issues which were repaired without adding
case-, compiler-, symbol-, or RVA-specific acceptance rules:

1. Executable alias bridges now accept only checked state-preserving no-op
   bytes or a direct short jump to the canonical cutpoint. Trap and zero-fill
   coverage can no longer be promoted into semantic aliases.
2. Terminating external calls receive an explicit generated fallback loop, so
   the architectural return address is mapped while the environment contract
   proves the return path unreachable.
3. Normalized block behavior has one canonical generated owner, shared by
   segment and acceptance proofs.
4. Broad simplification of segment/acceptance behavior equality was replaced
   by explicit equality rewrites, avoiding simplifier step exhaustion and
   making the proof intent local.

## Reproduction

```bash
nix develop --command spaghetti-extractor stage-a-fuzz-generate \
  --profile phase0-winapi-lockstep-v1 \
  --toolchain llvm-msvc \
  --external-profile profiles/pe32-kernel32-console-lockstep-v1.json \
  --out /tmp/spaghetti-phase0-llvm-v3 \
  --force

nix develop --command spaghetti-extractor stage-a-fuzz-run \
  --corpus /tmp/spaghetti-phase0-llvm-v3/corpus.json \
  --out /tmp/spaghetti-phase0-llvm-v3-run \
  --flake . \
  --builders-file nix/stage-a-builders
```

For the fast static gate, add `--stop-after-static-preflight`. Runtime behavior
tests remain gated on the final Stage A pass.

## Remaining Feasibility Work

Phase 1 must implement the four semantic templates, transformations, isolated
negative mutations, and deterministic 24-positive/12-negative corpus. Phase 2
must add checked automatic violation production and reduction while preserving
the same final theorem authority. Phase 3 must compare positive coverage,
negative discrimination, generic-rule growth, and cold/warm performance before
approving discovery mode or the Stage B opaque-artifact round trip.

The next independent toolchain checks should use a Windows SDK import library
where licensing and environment permit and add compiler-generated C. Neither
may weaken the binary-level proof contract or become a trusted source of
mapping facts.
