## Keystone and canonical semantic boundary

The keystone is `linked-semantic-module-v2` over
`executable-transfer-plan-v2`, with the following exact interpretation:

1. `executable-transfer-plan-v2` is the only executable semantic language.
2. `semantic-object-v1` is a content-addressed relocatable package over that
   language. It may package or reference transfer bodies, symbols, roots,
   relocations, objects, environment contracts, and provider requirements; it
   must not translate function behavior into a second semantic IR.
3. A packaged `semantic-object-v1` is the sole production input to the direct
   conservative semantic linker.
4. `linked-semantic-module-v2` records the deterministic may-realization
   universe, stable definitions, typed relocations, genuine semantic holes,
   typed residual runtime obligations, and only canonical site-local
   frontiers. It does not embed a second copy of executable semantics.
5. Whole-program must-provenance, solvers, emulators, fuzzers, CBMC examples,
   differential execution, and tests remain analysis or veto mechanisms.
   Their failure cannot remove may-reachable behavior, grant authority, or
   change production module identity.
6. Generated Behavioral C explicitly owns every original definition in the
   faithful configuration. Qualified portable providers may replace exact
   content-addressed slices in hybrid configurations. No selection may fall
   back silently.

This is one semantic language, one relocatable packaging boundary, one
production link algorithm, one total provider selection, and one native
realization/deployment chain. It is not permission to create a universal
artifact containing analysis, source presentation, runtime state, and PE
layout.

## Non-negotiable invariants

- Preserve fail-closed authority and veto-only diagnostics.
- Preserve the complete root, direct-edge, exception, outcome, relocation,
  object, and provider-requirement universes under migration and broadening.
- Distinguish semantic closure, executable qualification, and deployed
  completion in every status surface.
- Bind every selected source and object to the pinned compiler, checker,
  linker, realization, deployment, and candidate hashes.
- Keep PE layout, ingress bridges, TLS, SEH, loader surfaces, and candidate
  observation downstream of semantic linking.
- Keep generated faithful C immutable. Operator-authored C lives only in a
  separately hashed source package and qualifies only its selected slice.
- Migrate every in-tree consumer before retiring a production format, reader,
  constructor, input, command, or compatibility path.
- Prefer the existing Python implementation, Nix content-addressed phases,
  and measured algorithmic improvements. Add a dependency, cache, daemon,
  proof format, or Rust kernel only after a real vertical demonstrates that it
  is necessary.
- Tests and evaluator comparisons can veto a claim but cannot authorize one.
