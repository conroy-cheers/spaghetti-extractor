# Reusable local caller composition: acceptance audit

The common caller checker now supports real finite caller operations described
by checked boundary data, with ordinary C implementations and independently
validated suppliers. Save and guarded UI replacement use this rule. The reserved
resource-ID-97 notice was added after freezing the production implementation.
Public editing, rejection, repair, contract refinement and compatible neighbor
reuse have been demonstrated. All eight milestone exits are met within the
selected finite caller domain and the authority limits below.

This record supersedes the earlier checkpoints in [current-goal](../current-goal.md).
It covers the finite caller milestone, not the complete
[independent lifting roadmap](../independent-portable-lifting-plan.md). The rule
currently accepts two checked supplier families and named, unverified runtime
imports. General lifecycle/effect composition, recursive callers, callbacks,
concurrency and arbitrary representation changes require further checked rules.
Unsupported forms fail explicitly; a declared effect does not become a theorem.

## Reserved operation and contract refinement

The actual Metapad PE has SHA-256
`685989bad8d8119eddbb49e36006d8ac9155c45d69dee060807368241c8e58ce`;
the canonical transfer plan identity is
`33f6ad7e3e6b1541d59ed2279b14621e2cb9bcf7582b8957bbc6fd727acf2590`.
The reserved operation owns `0x12c0` and `0x12ce`, fetches resource 97 at `0x12c9`,
passes its returned shared view and the current window to MessageBoxA at `0x12d6`,
and continues at `0x12dc`. Its recorded incoming edge is from `0x12ba`. This proves
the selected operation under its entry contract, not whole-routine reachability.

The original C was regenerated from that plan and matched the candidate's original
file bytes. Its definition is not a renamed ID-31 original slice. The ordinary
[show-error.c](../../tests/fixtures/metapad-resource-callers/error-notice/show-error.c)
calls resource retrieval, reads the current window, and invokes the message service.
The common engine handles both ABI calls and continuation stack slots. A future
window-argument slot may overlap the earlier CALL return word while uninitialized;
actual native writes establish when it becomes readable. Initialized caller slots
remain protected from child writes.

Final review widened the caption view from one byte to 500 bytes, matching the
retained native fixture's bounded span. C source and signature types stayed fixed.
The public checker correctly invalidated `contract`, `interface_intent`,
`native_calls` and `boundary`; a new proof passed. Subsequent repair and compatible
supplier edits reused it. A stable signature is therefore insufficient for reuse.
Neither view size nor a returned pointer proves NUL termination or lifetime.
The earlier ID-31 development case remains a narrower address-transport experiment.

The two real supplier implementations have compiled portable objects of 16,631
and 17,415 bytes. Both have validated source and original-comparison evidence.
The consumer model stays at 773,907 bytes, with 63 function bodies and no resource
helper body. Current readers validate reused evidence with process execution and
consumer rendering forbidden. Supplier growth is real compiled-code growth;
reuse is not merely a renamed fixture or repaired-source cache hit.

Input validation includes recursive supplier evidence checking. Dependency
inventory and GOTO compilation are distinct compiler phases.

Reserved source-package input handling takes 0.0018s and host/PE32 source
compilation takes 0.0539s, separately from the proof phases above.
Reserved wrong-edit checking takes 14.59s; repair and compatible neighbor checks
take 6.78s and 7.00s with zero consumer proof work. Public work-package baseline
and boundary repair take 6.22s and 5.81s and likewise reuse the proof. Inspection,
start, proposal and adoption have separate command records. `reserved-refined-costs-v1.json`
and `freeze-workflow3-costs-v1.json` retain the detailed phase data.

The generic migration increased models relative to the earlier specialized
387,880/861,641-byte save/UI baseline. The intermediate typed-relation and paired
adapter measurements in the goal journal retain the incremental size/query
comparisons; this audit does not attribute the full cumulative increase to a
single mechanism. The last production fix
and refreshed suppliers leave the generic baseline C/GOTO bytes, semantic query
bindings and options unchanged. Its higher observed solver time therefore cannot
be attributed to model growth; no controlled cause for the timing variation is
claimed. See `freeze-workflow3-model-regression-v1.json`.

Retained plan validation and exact-slice generation take 1.661s and 0.0047s.
Canonical resource-evidence rebinding takes 5.87/4.44s, retaining portable objects
and original C. An earlier producer change conservatively invalidated cleanup
receipts through a shared utility import: current entry/loop/tail refreshes take
52/21/175s with byte-identical models. The tail's initial 60s timeout and successful
240s-limit retry are retained. Neighbor tail/composition then reuse current proofs
with zero model/compiler/solver work. No pilot rebuild was needed.

These results identify two remaining performance costs: recursive evidence import
and conservative transitive producer invalidation. Small caller models do not
remove either. Local implementation independence is demonstrated; zero command
overhead is not claimed.

## Native, link, export and portability boundaries

The existing PE32/Wine consumer test uses actual allocation, memory, edit-control,
resource and message services, including both real resource implementations.
Its ten tests retain current declared inputs. Native source preparation, compilation,
linking and execution remain separate from proof costs: the retained resource
fixture measures 0.037s preparation, 0.630s compilation, 0.040s linking and 7.783s
for 30 original/C executions, including Wine/display startup. These are prior
measured fixture costs; the current test rerun independently checks correctness.
It is finite runtime validation, not a formal runtime theorem or deployment link.
`caller-final-native-binding-v1.json` additionally matches the generated native
fixture's save/UI sources, headers and original slices to current proofs and both
resource implementations/headers to their current source certificates.

This fixture does not qualify the new ID-97 operation's complete concrete runtime
domain. Its MessageBox assumptions, NUL termination, reentrancy, invocation
failures, nonreturn and surrounding reachability remain unverified. The local
proof explicitly reports `runtime_compatibility: unverified`,
`whole_component_complete: false` and `activation_authorized: false`.

The semantic-provider importer still requires the existing contextual/conditional
proof packet, checked binding/refinement, exact-slice policy and complete coverage.
Finite caller-check receipts are not that packet. Qualification/selection tests
cover missing facets, stale contract identities, faithful/hybrid/portable mode
distinctions and forged native selection. Native ingress/export tests cover actual
object anchors, bridge derivation, fault/exception portals and rejected missing
object projections. Target SDK, registry and retired-architecture gates preserve
the integration surface. Hello, jq and DX-Ball target inputs are unchanged; their
existing pilot, strong portable dispatch/link, export and portability requirements
remain necessary for activation. No whole-pilot completion is claimed here.

## Validation record

Public audits bind actual preparation paths, exact source files, current producer
identities, supplier receipts, query files and compiled inventories. The production
freeze excludes fixtures, tests, documentation and generated JSON inventories;
all 783 frozen files must remain unchanged for the acceptance case to count.
Final targeted and gate products are recorded under `caller-final-*`.
All 151 targeted tests across 20 Nix shards pass without skips; every declared
input matches the current worktree. This includes every changed test file plus
provider qualification/selection and native ingress/export coverage. The ten
native tests also pass without skips, with 283 current input hashes. The target
SDK, repository metadata, format registry, production Python lint and retired
architecture gates all pass. `git diff --check` passes.

The repository boundary shard has two known size failures: 31 of 33 tests pass.
The seven reported oversized files are recorded separately; this is not a claim
that every repository test passes. No unrelated work, commit, publication, pilot
activation or deployment was performed.
